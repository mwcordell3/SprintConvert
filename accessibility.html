Accessibility

What we've done to make this site usable for everyone, and how to report issues.

Standards we follow

We aim to follow practical Web Content Accessibility Guidelines (WCAG) 2.1 Level AA. We make no certification claims; this is a best-effort, ongoing commitment.

What's in place today

  • Semantic HTML — header, nav, main, section, footer landmarks throughout.
  • Skip-to-content link as the first focusable element on every page.
  • Visible labels on every form field. Placeholder text is never the only label.
  • aria-describedby for help and error text on form inputs.
  • aria-live regions on errors and result updates so assistive technology announces changes.
  • Full keyboard navigation. No mouse-only interactions.
  • Visible focus styles on all focusable elements.
  • High color contrast between text and background.
  • No reliance on color alone to communicate status — tier names are always shown as text.
  • No flashing animations. Reduced-motion users have all transitions removed.
  • Layout is usable at 200% browser zoom on a 360-pixel-wide viewport.
  • All buttons use clear text labels. Icon-only controls are avoided.
  • Error messages are clear, specific, and tied to the field that caused them.
  • Tables and cards reflow responsively without horizontal scrolling.
  • Decorative images use empty alt attributes; meaningful images use descriptive alt text.
  • No keyboard traps.
  • The contact path is plain text, not gated behind any modal or carousel.
  • Plain language is used wherever possible.

Known limitations

We are an early-stage, low-budget educational site. We do not yet have a full third-party accessibility audit or assistive-technology test matrix. If you encounter an issue with a screen reader, voice control, switch device, or any other assistive technology, please report it so we can fix it.

Report an issue

For accessibility issues, see the contact page. Specific reports — what page, what action, what expected vs. actual behavior — help us fix things faster.
